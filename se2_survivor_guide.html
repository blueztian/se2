Configuration Management (CM)

The process of identifying, organizing, tracking, and controlling changes made to project assets to maintain integrity and consistency over time.

Taglish Translation:

Ito yung pag-organize at pag-track sa lahat ng files at codes niyo para hindi kayo nag-ooverwrite-an ng gawa. Iwas din ito sa "gumagana naman sa PC ko ah" na palusot kasi pare-parehas kayo ng setup at versions na gamit.

Configuration Items (CIs)

Any project component that must be managed and tracked. Examples:

  • Source Code
  • Requirements
  • DB Schemas
  • Config Files

Configuration Management Activities

1. Configuration Identification

Determine what should be controlled, naming conventions, and directory structures.

2. Configuration Control

Ensures all changes are requested, reviewed, approved, implemented, and verified.

3. Configuration Status Accounting

Maintains records of current versions, pending/approved changes, and release history.

4. Configuration Audits

Verify documentation matches implementation and no unauthorized modifications exist.

Version Control & Git

A system that records changes made to files over time so previous versions can be recalled.

Basic Git Concepts

Repository: Storage location Commit: Saved snapshot Branch: Independent line Merge: Combines changes Clone: Copies repo Pull: Download updates Push: Upload commits

Centralized (CVCS)

One central server stores the repository. (e.g., SVN)

Risk: Single point of failure. Needs network access.

Distributed (DVCS)

Every developer has a complete copy of the repository. (e.g., Git)

Pro: Work offline, faster, multiple backups.

Git Workflow Branches

Main: Production-ready code. Official release history.

Develop: Integration hub for new features before release.

Feature: Where you build a new function (won't disturb main code).

Release: Buffer branch prepping code for production (final touches/bug fixes).

Hotfix: Swift avenue for fixing critical bugs in production.

Taglish: Gumagawa tayo ng 'branch' (parang alternate universe) para pag nagkamali ka ng code, hindi masisira yung main project ng buong team. Pag tapos at okay na, tsaka mo i-Me-Merge sa Main.

CI/CD & Releases

Continuous Integration (CI)

Automatically integrating code changes into a shared repository several times a day. Triggers automated Builds and Tests.

Continuous Deployment (CD)

Code changes pass automated tests and go straight to production automatically, skipping manual approval.

Build & Release Management

Build Management: Converting source code into executable software (Compiling, Testing, Packaging).

Major Release (v3.0)
Significant new features/changes.
Minor Release (v3.2)
Enhancements without major changes.
Patch Release (v3.2.1)
Fixes bugs or security vulnerabilities.

Software Testing Fundamentals

The process of evaluating and verifying that a software application meets its specified requirements and works as intended.

Taglish Translation:

Ito yung sinisigurado mong walang bug yung gawa niyo at tama yung ginagawa bago pa i-release. Kumbaga, quality control bago i-benta para hindi magalit yung client.

Software Testing Life Cycle (STLC)

1 Requirement Analysis: Study docs, clarify ambiguities.
2 Test Planning: Define strategy, schedule, assign tools.
3 Test Case Dev: Write test cases and prepare test data.
4 Environment Setup: Install software, configure DBs/servers.
5 Test Execution: Run tests, record results, report defects.
6 Defect Tracking: Log, prioritize, verify fixes, run regression.
7 Test Closure: Evaluate results, document lessons learned.

Levels of Testing

1. Unit Testing

Performed by: Developers

Tests individual functions, methods, or classes to ensure each unit functions correctly.

Taglish: "Gumagana ba mag-isa 'tong maliit na Login function ko?"

2. Integration Testing

Performed by: Developers

Tests whether multiple modules work correctly together (Data exchange).

Taglish: "Nakakapag-usap ba yung Login page at yung Database natin?"

3. System Testing

Performed by: QA Engineers

Tests the complete integrated application (end-to-end workflows).

Taglish: Test ng buong app. Mula umpisa hanggang dulo.

4. Acceptance Testing

Performed by: Client / End Users

Determines whether software is ready for release.

  • UAT: Users verify business needs.
  • Alpha: Internal controlled environment.
  • Beta: Real-world limited release.

Types of Software Testing (Click to Flip)

Smoke & Sanity

Smoke: Checks major features on a new build.
Sanity: Verifies a specific bug fix.

Smoke = Bumukas ba? Sanity = Naayos ba yung sira?
Regression

Ensures existing features still work correctly after new changes or fixes are made.

Siguraduhing hindi nakasira ng lumang code yung bago mong update.
Performance

Measures system speed, response time, throughput, CPU, and memory usage.

Mabilis ba mag-load? Magastos ba sa RAM?
Load & Stress

Load: System behavior under expected user traffic.
Stress: Pushing beyond capacity to find the breaking point.

Load: Kaya ba ang 5k users? Stress: Sa pang-ilang user siya mag-crash?
Security

Checks for vulnerabilities like SQL Injection, XSS, and authentication flaws.

Madali bang ma-hack? Ligtas ba data ng users?
Usability

Determines if the application is easy to use, intuitive, and clearly labeled.

User-friendly ba? Di ba nakakalito ang mga buttons?
Compatibility

Checks operation across different browsers, operating systems, devices, and screen sizes.

Gumagana ba sa Chrome, Safari, iPhone, at Android?

Software Testing Automation

Using software tools and scripts to execute tests automatically, compare results, and generate reports with minimal human intervention.

Taglish: Imbes na ikaw yung paulit-ulit na magta-type at magki-click para mag-test, gagawa ka ng script (bot) para siya na ang gumawa. Mabilis at walang pagod, pero medyo matagal i-setup sa umpisa.

Benefits

  • Faster execution and higher accuracy.
  • Reusable test scripts.
  • Supports CI/CD pipelines.
  • Enables frequent regression testing.

Limitations

  • High initial setup cost.
  • Requires programming/scripting skills.
  • Scripts need maintenance when the app changes.

When to Automate?

YES (Automate these)
  • Repetitive & stable tests
  • Time-consuming tests
  • Regression & Data-driven
  • Cross-browser tests
NO (Manual testing)
  • One-time tests
  • Frequently changing features
  • Exploratory testing
  • Usability testing

Common Automation Tools

Selenium (Web apps) Cypress (Modern web) Playwright (Cross-browser) Appium (Mobile apps) JUnit (Java unit) NUnit (.NET unit) pytest (Python)

Software Quality Assurance (SQA)

A systematic approach used to ensure that software development processes and products meet established quality standards.

SQA vs Quality Control (QC)

Quality Assurance (SQA)

  • Focuses on processes
  • Prevents defects
  • "Are we following the right process?"

Quality Control (QC)

  • Focuses on products/results
  • Detects defects (Testing)
  • "Does the product work correctly?"

Taglish Translation:

QC (Testing) = Sila yung taga-hanap ng bug sa gawa niyo.
SQA = Sila yung nagaayos ng sistema niyo para *hindi* na kayo gumawa ng bug sa susunod (Preventive).

SQA Documentation

Provides evidence that quality processes are planned, performed, and monitored.

1. SQA Plan (SQAP)

Describes how quality will be managed (objectives, standards, roles).

2. Test Plan

Defines what to test, how to test, who tests, and expected results.

3. Test Cases & Results

Specific tests to be performed and the Pass/Fail record.

4. Defect/Bug Reports

Records problems (ID, Description, Severity, Steps to reproduce).

Quality Audits & Process Improvement

An independent examination to check compliance with established standards. It asks: "Are we following the agreed-upon processes?"

Corrective Action

Addresses the cause of an existing problem.

Nasunugan na, kaya bumili ng fire extinguisher at inayos ang wire.

Preventive Action

Attempts to prevent a potential problem from occurring.

Bumili agad ng fire extinguisher bago pa man may masunog.
